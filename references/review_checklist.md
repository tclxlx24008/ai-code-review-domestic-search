# 代码审查检查清单

按类别组织的系统性代码审查详细检查清单。

## 1. 正确性与缺陷

### 逻辑与控制流
- [ ] 所有条件分支是否可达且正确？
- [ ] 循环边界是否正确（差一错误）？
- [ ] switch 语句是否穷举（或有 default 分支）？
- [ ] 布尔条件是否正确（如 `&&` vs `||`，`==` vs `=`）？
- [ ] 是否存在跳过必要清理或副作用的提前返回？
- [ ] 是否存在永远无法执行的死代码路径？

### 空引用与引用安全
- [ ] 使用点处是否有引用可能为 null？
- [ ] 解引用前是否进行了空检查？
- [ ] 是否存在潜在的 `NullReferenceException` 路径？
- [ ] 可空引用类型是否正确标注（C# 8+）？
- [ ] 对可能为空或 null 的集合操作是否安全？

### 并发与线程
- [ ] 共享可变状态的访问是否正确同步？
- [ ] 是否存在潜在的竞态条件？
- [ ] 异步操作是否正确等待（没有无意的 fire-and-forget）？
- [ ] 是否避免了 `async void`（事件处理器除外）？
- [ ] 是否存在因 `.Result` 或 `.Wait()` 导致异步代码死锁的风险？
- [ ] `CancellationToken` 参数是否正确传递？

### 异常处理
- [ ] 预期异常是否被正确捕获和处理？
- [ ] catch 块是否具体（非裸 `catch` 或 `catch(Exception)`）？
- [ ] 重新抛出时是否保留了异常状态（`throw;` 而非 `throw ex;`）？
- [ ] finally 块是否用于资源清理？
- [ ] 自定义异常是否有意义且结构良好？

### 数据与状态
- [ ] 数据转换是否正确（序列化、反序列化、映射）？
- [ ] 是否存在整数溢出或下溢风险？
- [ ] 浮点数比较是否正确处理？
- [ ] 日期时间操作是否考虑时区？
- [ ] 是否存在隐式类型转换问题？

## 2. 安全性

### 输入校验
- [ ] 所有外部输入是否经过校验（HTTP 请求、查询参数、请求头）？
- [ ] 输入在用于查询、命令或输出前是否经过清洗？
- [ ] 是否存在 SQL 注入风险（查询中原始字符串拼接）？
- [ ] 是否存在 XSS 风险（未转义输出到 HTML）？
- [ ] 是否存在命令注入风险（用户输入进入 shell 命令）？
- [ ] 文件路径是否校验了目录遍历攻击？

### 认证与授权
- [ ] 所有敏感端点是否存在认证检查？
- [ ] 授权是否正确执行（不仅仅是认证）？
- [ ] 是否存在权限提升风险？
- [ ] 令牌/凭据是否正确验证（有效期、签名）？
- [ ] 敏感数据是否有正确的访问控制？

### 数据保护
- [ ] 密钥/凭据是否安全存储（不在源代码中）？
- [ ] 敏感数据在存储和传输中是否加密？
- [ ] 错误消息中是否存在信息泄露风险？
- [ ] 个人身份信息（PII）是否正确处理？
- [ ] 日志语句是否暴露了敏感数据？

### 依赖与配置
- [ ] 是否存在已知漏洞的依赖？
- [ ] 安全头是否正确配置（CORS、CSP、HSTS）？
- [ ] 默认配置是否安全（非生产环境 debug 模式）？
- [ ] 是否存在可被利用的不安全默认值？

## 3. 性能

### 数据库与查询
- [ ] 是否存在 N+1 查询模式（循环中查询）？
- [ ] 查询是否正确索引和优化？
- [ ] 事务范围是否尽可能窄？
- [ ] 连接池是否正确配置？
- [ ] 大结果集是否分页？

### 内存与分配
- [ ] 热路径中是否有不必要的对象分配？
- [ ] 大对象是否正确释放或池化？
- [ ] 是否存在内存泄漏（事件处理器订阅、静态引用）？
- [ ] 容量已知时集合是否预分配大小？
- [ ] `IDisposable` 资源是否正确释放？

### 缓存与 I/O
- [ ] 频繁访问且很少变更的数据是否缓存？
- [ ] 缓存失效策略是否正确？
- [ ] 外部调用是否尽可能批量处理？
- [ ] 是否有应该异步但仍是同步的 I/O 操作？
- [ ] 所有外部调用是否配置了超时？

### 算法与数据结构
- [ ] 算法复杂度是否适合预期的数据规模？
- [ ] 是否存在可以优化为 O(n) 或 O(n log n) 的不必要 O(n²) 操作？
- [ ] 是否使用了合适的数据结构（如 HashSet 用于查找）？
- [ ] 是否存在不必要的数据拷贝或转换？

## 4. 可靠性与弹性

### 错误处理与恢复
- [ ] 所有外部依赖故障是否优雅处理？
- [ ] 瞬态故障是否实现了重试逻辑？
- [ ] 重试策略是否合理（指数退避、最大重试次数）？
- [ ] 对可用性有顾虑的依赖是否使用了熔断器？
- [ ] 失败场景是否定义了降级/默认行为？

### 资源管理
- [ ] 连接、流和句柄是否正确关闭/释放？
- [ ] 是否存在资源耗尽场景？
- [ ] 外部 API 是否遵守速率限制？
- [ ] 是否存在可能无限增长的无界队列或集合？
- [ ] 后台任务是否正确管理且可取消？

### 可观测性
- [ ] 日志是否足够用于调试生产问题？
- [ ] 日志级别是否合适（不太冗余，不太稀疏）？
- [ ] 分布式追踪标识是否正确传播？
- [ ] 所有关键依赖是否定义了健康检查？
- [ ] 关键操作是否上报了指标（延迟、错误率）？

## 5. 可维护性

### 可读性
- [ ] 命名是否描述性强且一致（变量、方法、类）？
- [ ] 代码是否自文档化，复杂逻辑是否需要注释？
- [ ] 方法是否聚焦且不过长（建议 < 30 行）？
- [ ] 类是否聚焦且职责单一？
- [ ] 嵌套深度是否合理（建议 < 4 层）？

### 结构与设计
- [ ] 是否存在大量代码重复？
- [ ] 抽象层次是否恰当？
- [ ] 组件间耦合是否合适？
- [ ] 接口是否稳定且定义良好？
- [ ] 依赖注入是否一致使用？

### 可测试性
- [ ] 代码是否可以隔离进行单元测试？
- [ ] 依赖是否注入而非硬编码？
- [ ] 是否存在使测试困难的副作用？
- [ ] 测试覆盖是否适合逻辑复杂度？

### 文档
- [ ] 公共 API 是否有文档？
- [ ] 复杂算法或业务规则是否有说明？
- [ ] 设计决策是否有文档记录（为什么，而不仅仅是什么）？
- [ ] 破坏性变更或迁移路径是否有标注？

## 6. 最佳实践

### 语言特定 (C# / .NET)
- [ ] 是否遵循 C# 惯用法（表达式体成员、模式匹配）？
- [ ] async/await 模式是否正确？
- [ ] LINQ 操作是否高效（避免多次枚举）？
- [ ] 字符串操作是否使用正确的比较方式（序数 vs 区域性）？
- [ ] 结构体是否恰当使用（小型、不可变的值类型）？

### 框架特定
- [ ] 是否遵循框架约定（路由、中间件、过滤器）？
- [ ] 依赖注入是否正确使用（避免服务定位器反模式）？
- [ ] 配置选项是否使用 Options 模式？
- [ ] HTTP 客户端实例是否正确管理（IHttpClientFactory）？

### API 设计
- [ ] API 契约是否稳定且向后兼容？
- [ ] 错误响应是否一致且信息充分？
- [ ] API 版本是否正确处理？
- [ ] 是否有限流和节流措施？

### 版本控制
- [ ] 提交是否聚焦且描述良好？
- [ ] 敏感文件是否排除在版本控制之外？
- [ ] 是否存在意外变更（调试代码、注释掉的代码）？
- [ ] 合并冲突是否正确解决？
